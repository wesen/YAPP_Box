# Migration Guide: Path 1 (A→B) Refactor

## What changed on 2025-11-17

We landed Path 1 (A→B), a repo-wide refactor of the YAPP DSL module builders. The headline changes:

- **Generated `Decode()` helpers** — every module now receives a typed `Decode(items []map[string]any) ([]YourModuleItem, error)` generated by `schemagen`.
- **Typed builders** — module `Build` functions take `[]YourModuleItem` instead of `[]map[string]any`.
- **ArrayDecl IR** — `registry.FeatureModule.Build` returns `[]registry.ArrayDecl`, allowing single-array and multi-array modules to share the same plumbing.
- **Enforcement** — generated wrapper tests plus `golangci-lint (forbidigo)` ensure we never reintroduce `yaml.Marshal` / `yaml.Unmarshal` inside module builders.

Any module (existing or new) must adopt this contract before merging.

## Who needs to act?

- **Module authors** updating legacy features or creating new ones.
- **Release engineers** cherry-picking fixes across branches that predate the refactor.
- **Doc/tooling contributors** who reference the old marshal/unmarshal pattern in docs, snippets, or tutorials.

If you are only consuming YAPP as an end user, no action is required—this is a developer-facing change.

## Migration checklist for an existing module

1. **Regenerate code**
   ```bash
   go run ./cmd/schemagen discover
   ```
   This emits the `Decode()` helper, typed structs, and wrapper tests for your schema.

2. **Update `module.go`**
   - Change the signature to `func Build(items []YourModuleItem) ([][]any, error)`.
   - Remove any `yaml.Marshal` / `yaml.Unmarshal` conversions. Use the typed `items` slice directly.
   - Keep positional array construction + flag encoding logic as-is; only the input type changes.

3. **Update `registry.go`**
   ```go
   func (m *module) Build(items []map[string]any) ([]registry.ArrayDecl, error) {
       typed, err := Decode(items)
       if err != nil {
           return nil, err
       }

       rows, err := Build(typed)
       if err != nil {
           return nil, err
       }

       return []registry.ArrayDecl{{
           Name: "yourScadArray", // matches schema scad_array
           Rows: rows,
       }}, nil
   }
   ```
   - Multi-array modules (like `cutouts`) should iterate over the map returned by their typed builder and append a `registry.ArrayDecl` per array name before returning.

4. **Run the generated wrapper tests**
   ```bash
   go test ./pkg/yappgen/modules/<yourmodule>
   ```
   The generated `TestBuild_UsesGeneratedDecode` ensures your registry wrapper actually calls `Decode()`, while `TestBuild_ReturnsArrayDecl` verifies the ArrayDecl contract.

5. **Run the standard suite**
   ```bash
   go test ./pkg/yappgen/modules/... && go build ./...
   ```
   For release candidates, also regenerate the SCAD baselines called out in the ticket playbooks (currently `examples/04-features.yaml` and `examples/yapp-mvp-pcbstands-cutouts.yaml`) and diff them against `/tmp/refactor-baseline`.

6. **Deal with linter errors**
   - `golangci-lint run --config .golangci.yml`
   - If you see `forbidigo` errors complaining about `yaml.Marshal`/`yaml.Unmarshal`, it means an old builder still exists—repeat step 2.

7. **Update docs and tasks**
   - Reference the new pattern in PR descriptions.
   - If you touched tutorials or playbooks, add a changelog entry via `docmgr`.

## Adding a brand-new module after the refactor

1. Follow the updated [Module Authoring Guide](../tutorials/yapp-module-authoring-guide.md). It already documents the typed builder + ArrayDecl wrapper pattern.
2. Ensure your schema includes at least one `expect_valid` test case—schemagen uses the first one to seed the generated Decode + Build wrapper tests.
3. Whenever you re-run `schemagen discover`, commit the regenerated `schema_gen*.go` files alongside your manual edits.

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| `forbidigo: Do not use yaml.Marshal in module builders` | Builder still marshals map inputs | Remove marshal/unmarshal, rely on typed `Decode()` |
| `arrayFeatureModule foo returned 0 arrays, expected 1` | Registry wrapper returned `nil` or empty rows | Ensure `Build` returns at least one row when input is non-empty; verify `scad_array` name matches the schema |
| `TestBuild_UsesGeneratedDecode` fails | Registry wrapper bypassed `Decode()` or swallowed its error | Call `Decode()` before invoking the typed builder, and propagate errors directly |
| SCAD diff vs baseline | New typed builder changed ordering or default handling | Double-check `ApplyDefaults()` calls and positional parameter order; compare against the old marshal/unmarshal version for discrepancies |
